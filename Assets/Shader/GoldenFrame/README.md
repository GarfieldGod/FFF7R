# GoldenFrame · Shader 版

同一个金框，**不用任何贴图**：框、辉光、角标、动画全部由 GPU 在片元着色器里算出来。
和 `../frames/` 里那 36 张烘焙帧是同一个设计，参数一一对应，可以互相对照。

为什么会有两版、什么时候该用哪一版，见 `../../README.md` 的"形态判定"一节。
结论先说：**要改颜色、改速度、随便什么尺寸 → 用这一版；要火焰烟雾那种手绘有机形态 → 用烘焙帧。**

---

## 放进 Unity 工程

**把整个 `GoldenFrame/` 文件夹拷进 `Assets/Shader/`**（或任意其它目录），结果是：

```
Assets/Shader/GoldenFrame/
├── GoldenFrameUI.shader        效果本体（UI 和 3D 共用同一个 shader）
├── GoldenFrameUI.cs            UGUI 用：尺寸桥接组件
├── GoldenFrameMesh.cs          3D 用：把 Quad 的实际尺寸喂给 shader
├── Editor/
│   └── GoldenFrameMenu.cs      两个一键建对象菜单
└── README.md                   这份文档（Unity 不认 .md，放不放都行）
```

文件夹名就是特效名，**不用改名**；`Assets/Shader/` 换成 `Assets/VFX/`、`Assets/Art/` 也一样能用。

**三条不能动：**

1. `Editor/` 这个**文件夹名不能改**，里面的 `.cs` 也不能挪出来。它是编辑器脚本，混进运行时程序集会编译失败。
2. **`.shader` 和 `.cs` 的文件名不要改**。Unity 要求 MonoBehaviour 类名与文件名一致，`GoldenFrameUI.cs` 里的类是 `GoldenFrameUI`。
3. **`.shader` 不能放进 `Editor/`**，否则运行时 `Shader.Find` 找不到它。

放好之后 `Assets` 会自己刷新编译一次，Console 没红色就成功了。

> **关于 `Shader "FFF7/UI/GoldenFrame"` 这串名字**
> 它是 shader 的 ID，只在材质球下拉里显示成树形，**和文件名、文件夹路径没有任何关系**，
> 叫什么都行，只要工程内唯一。这里用 `FFF7/UI/` 是跟随 ProjectSettings 的 `productName = FFF7`。
> 要改就改**两处**：`.shader` 第 10 行的 `Shader "..."`，和 `Editor/GoldenFrameMenu.cs` 里的
> `const string ShaderName`。改一处菜单就会弹"找不到 Shader"。

材质球不用手工建：点一次菜单会自动生成在 **shader 同级的 `Materials/GoldenFrame.mat`**（`GoldenFrameMenu.cs` 会反查 shader 的实际路径，所以整个文件夹放哪都行，不会跑到别的地方建目录）。

## 先把 shader 当成什么

一个片元着色器就是**对屏幕上每一个像素调用一次的函数**：

```
输入：这个像素在 UI 元素里的位置（uv，0~1）
输出：这个像素的颜色
```

没有别的。它不知道自己在卡牌上还是按钮上，也不知道有几帧——所有这些都由你传进去的参数和 `_Time` 决定。

所以"改效果"从来不是改流程，而是**改这个函数的算法或者它的输入**。这个框里，函数在算的是：

```
1. 这个像素离"卡牌边框"有多远？      → SDF（有符号距离场）
2. 距离落在 3mm、15mm 附近吗？        → 三道线
3. 距离很近但不在线上吗？             → 辉光
4. 在四个角、且落在 L 形里吗？         → 角标
5. 现在几点了？                       → 乘上呼吸系数（只有内层参与）
```

就这五行。下面所有参数都是在改这五行里的数字。

## 三分钟用起来

### 方式 A：一键（推荐）

```
菜单栏 → GameObject → UI → Golden Frame
```

会在当前 Canvas 下生成一个 `GoldenFrame` 对象，材质、组件、尺寸都配好了。

### 方式 B：手动五步

1. Canvas 下建一个空 UI 对象（`UI → Empty`），尺寸设成卡牌大小（比如 400 × 520）
2. 加 `Image` 组件：
   - **Source Image 留空**（不要拖任何 sprite，拖了会多出一张图叠在金框下面）
   - Color = 白色
   - **取消勾选 Raycast Target**（这是装饰层，不该挡点击）
3. Material 槽放 `GoldenFrame.mat`
   - 没有的话：项目里右键 `Create → Material`，Shader 选 `FFF7/UI/GoldenFrame`，改个名就行
4. 加 `GoldenFrameUI` 组件（`Add Component → FFF7R/VFX/Golden Frame UI`）
5. 运行

**尺寸随便设。** 线宽、圆角、角标会按比例自动缩放，观感和设计稿一致。
`_QuadW` / `_QuadH` 两个参数是组件自动写的，不要手改。

## 挂到世界里的物体上（棋盘格子 / 落子位）

能。而且**不要用 World Space Canvas**，直接挂一张 Quad 更省事：

| | 3D Quad（推荐） | World Space Canvas |
|---|---|---|
| 每帧开销 | 一个三角形，无 Canvas 重建 | Canvas 要重建网格、还要 GraphicRaycaster |
| 和 3D 的遮挡关系 | 深度测试，棋子会正常挡住框 | 靠 sortingLayer 排，和 3D 混排很别扭 |
| 尺寸 | Transform 缩放直接决定 | 要调 Canvas scale factor，动一次全局都变 |
| 文字 / 按钮 | 不能（纯特效） | 能 |
| 多格同时高亮 | 共用一个材质，能合批 | 每个 Canvas 一次 draw call |

### 一键

**先选中棋盘格子那个对象**（或者它的父物体），然后：

```
菜单栏 → GameObject → VFX → Golden Frame (Cell Quad)
```

生成的 `GoldenFrame_Quad` 会挂在选中的物体下面，尺寸 `0.5 × 0.5`（= 棋盘一格），
抬高 2 mm，材质 `GoldenFrame_World.mat` 已经配好。移动格子它自己跟着走。

### 手动四步

1. 建一个空物体当容器，**加 `MeshFilter` + `MeshRenderer`**（网格不用自己建，组件会塞一张 1×1 的）
2. 挂 `GoldenFrameMesh`（`Add Component → FFF7R/VFX/Golden Frame Mesh`）
3. 材质用 `GoldenFrame_World.mat`；自己建的话 **`深度测试` 必须选 `LessEqual`**
4. 尺寸靠 **Transform 的 Scale**：一格 = `(0.5, 1, 0.5)`，两格 = `(1, 1, 0.5)`

### 三个必须知道的点

**① 深度测试必须开。** UI 版用的是 `unity_GUIZTestMode`，那个全局变量只有 Canvas 会填，
挂在网格上时取到 0（= 不测深度），框会盖在棋子、桌子、甚至摄像机前面。
所以 shader 里改成了 `_ZTest` 参数：**UI 用 8（Always），3D 用 4（LessEqual）**。
`GoldenFrame_World.mat` 出厂就是 4。

**② 网格躺着，不用旋转。** 组件生成的 Quad 是 1×1、中心在原点、躺在 XZ 平面、法线朝 +Y。
Unity 里棋盘本来就是 Y 轴朝上、格面是 XZ 平面，所以旋转保持 `(0,0,0)` 就贴合了。
（shader 是 `Cull Off` 双面，即便转错方向也不会消失，但会镜像。）

**③ 抬高 2 mm 防闪。** 框和格面完全共面会 z-fighting，表现为框边一闪一闪。
放在格面上方 `0.002` 就够；如果棋子的底托很薄（比如 0.005），把框压到 0.001 也行。

**④ 网格是"延迟"建的，这是必须的。** 那张 1×1 Quad 由组件在运行时生成（`HideAndDontSave`，不随场景存盘），
所以 `.prefab` 里永远是 `m_Mesh: {fileID: 0}`，每次导入都会被重新建一遍。而给 `MeshFilter.sharedMesh`
赋值会让 Unity 立刻发 `OnMeshFilterChanged`，**`Awake` / `CheckConsistency` / `OnValidate` 阶段禁止发消息** ——
在那里建就是刷屏报 `SendMessage cannot be called during Awake, CheckConsistency, or OnValidate`。
所以 `GoldenFrameMesh` 里：`OnValidate` / 编辑模式下的 `OnEnable` 只登记一次 `delayedCall`，真正建网格放到下一次
编辑器 tick；预制体资产上干脆不建（存不下来，白建）；`Update` 只兜底补 `sharedMesh == null` 的情况。
**别把 `EnsureMesh()` 挪回 `OnValidate`。**

### 想让它跟着格子动

把 `GoldenFrame_Quad` 设为格子的子物体就行，Transform 会跟着父级走。
尺寸改父级缩放时，`GoldenFrameMesh` 会在 `Update` 里发现 `lossyScale` 变了并自动重写 `_QuadW/_QuadH`，
所以**不用管组件的参数**。代码里改完 transform 想立刻生效，可以调一次 `Apply(true)`。

### 什么时候才该用 World Space Canvas

只有一种情况：**框里还要放文字、按钮、进度条这类 UGUI 内容**，需要一个整体跟着 3D 物体跑的界面。
做法是 Canvas 的 `Render Mode` 设为 `World Space`，`RectTransform` 尺寸设成格子大小，
然后 Image + `GoldenFrameUI` 照常用；但记得把材质的 `深度测试` 改成 4，否则框会穿透棋子。

## 参数地图

在 Inspector 里选中 `GoldenFrame.mat`，展开就能看到。全部**实时生效**，边拖边看。

### Gold Lines · 金线

| 参数 | 默认 | 什么情况下调 |
|---|---|---|
| `外侧细线 · 内缩` | 0.0030 | 想让最外那根细线离卡片边缘更近/更远 |
| `外侧细线 · 线宽` | 0.0026 | 细线太细看不见时加到 0.004 |
| `主金带 · 内缩` | 0.0150 | 想让主金带整体靠近或远离边界 |
| `主金带 · 线宽` | 0.0098 | **最重要的一个**，框的"分量"由它决定 |
| `白热芯 · 线宽` | 0.0016 | 加宽会更"烧红"，太宽就变纯白描边了 |
| `圆角半径` | 0.0174 | 要更方的框就调到 0.006，要胶囊感就 0.03 |
| `卡外辉光余量` | 0.0400 | 卡片离 quad 边缘留多宽的空白。**框外已经不出光了**，这个值现在只影响"框在 quad 里占多大" |

> 长度单位是"设计单位"：1 = 1 米，卡片是 0.32 × 0.44。所以 0.0098 ≈ 9.8 mm。

### Colors · 配色

| 参数 | 默认 | 说明 |
|---|---|---|
| `外侧细线` | `#F7C263` | 偏暗的金，负责"框住"的边界感 |
| `主金带` | `#FF9E24` | 主色，饱和度高一点更好看 |
| `白热芯` | `#FFE6AD` | 近白，太黄就失去"烧白"的感觉 |
| `角标` | `#FFBD57` | 通常比主带亮半档 |
| `整体亮度` | 1.15 | 超过 1 时亮部会被钳到纯色，这是正常的"过曝" |

### Halo · 辉光

| 参数 | 默认 | 说明 |
|---|---|---|
| `衰减速度` | 20 | **越小辉光越宽**。想要大光晕调到 10，想要干净利落调到 40 |
| `辉光强度` | 0.50 | 主要的气味旋钮，0.3 很克制，0.8 很悬浮 |
| `向内衰减倍数` | 1.40 | 向内扩散比向外快多少倍。**小于 1.3 卡面会糊一层橙雾** |

> **辉光只在框里**。片元最后乘了一个 `haloMask`：外侧细线的外沿之外（`d > 0`，也就是卡面轮廓以外的
> 全部区域）辉光被硬切成 0，`rgb` 和 `alpha` 都是 0，**框外完全透明、一个像素都不写**。
> 早期版本没有这个上限，`exp` 衰减一路糊到 quad 边缘，画面上会出现一大圈"框外还在发光"的橙雾。
> 实测卡外 61 708 个像素的 `add` 最大值是 `0.000000`。
>
> 所以 `卡外辉光余量` 现在只影响"卡片离 quad 边缘多远"，不再决定光晕能扩多远。

### Contrast · 浅色卡面（白底看不见时看这节）

**为什么白底上会看不见**：这个效果本质是"发光"，而发光只能**加亮**。白底已经是 1.0，
金色加进去还是 1.0 —— 数学上没有任何余量，跟参数调多亮无关。现实里拿手电照白墙也一样看不出光斑。

所以这里不能靠"更亮"，只能靠两件事：

**① `实线底下压掉的辉光`（默认 0.75，主要手段）**

金带的亮度是 HDR（`整体亮度` 1.15 倍），辉光又叠了约 50% 上去，绿色通道被顶到 1.0
—— 金带退化成淡黄 `(1.00, 1.00, 0.25)`，在白底上就是一根"发白的细线"。
把这个值调到 0.75 之后，金带恢复成饱和的 `(1.00, 0.85, 0.19)`，白底上一眼就能看见，
**而且完全不需要暗边**。改这个值不会影响框外的光晕。

**② `深色描边`（默认 0 = 关闭，可选）**

在主金带外侧压一圈深褐。白底上对比更强，**但代价是会在光晕里切出一条暗边**，
任何底色上都看得到，深色卡面上尤其像贴了一圈黑胶带。所以默认关。

| 参数 | 默认 | 说明 |
|---|---|---|
| `实线底下压掉的辉光` | 0.75 | **白底发白的真正原因**。1.0 = 完全压掉（最饱和），0 = 保留原来的加色叠加 |
| `深色描边 · 强度` | **0.00** | 0 = 关。**非 0 就会出暗边**，只在浅色卡面还嫌不够时开到 0.3～0.4 |
| `深色描边 · 线宽` | 0.0035 | 打开描边时的宽度，0.002～0.004 比较不刺眼 |
| `深色描边 · 颜色` | `#0E0803` | 接近黑褐。想让它像"阴影"而不是"黑边"，可以调成暖褐 `#3A2410` |

### Brackets · 四角提示键

| 参数 | 默认 | 说明 |
|---|---|---|
| `离边距离` | 0.0320 | 角标整体离卡片边缘多远 |
| `臂厚` | 0.0062 | 太细会像装饰线，太粗会顶到主金带 |
| `臂长` | 0.0480 | 长臂更"标注感"，短臂更"点缀感" |
| `斜刻长度` / `宽度` / `离边距离` | 0.020 / 0.0016 / 0.0495 | L 内凹处那道 45° 斜刻，**横跨**角平分线，四角 = 同一形状转 90° |

**斜刻是两个正交的选择，别混成一个**：

| 选择 | 效果 | 公式 |
|---|---|---|
| 沿哪条线（**横跨** vs 顺着） | 横着切 = "切口"；顺着指进卡心 = "箭头"。差 90°，气质完全不同，要的是**横跨** | `sign.y, -sign.x`（把指心方向转 90°） |
| 四个角怎么摆（**旋转** vs 镜像 / 屏幕常量） | 只有旋转才满足"左下角转 90° == 左上角" | 用 `sign(p)` 还原四角，不用 `abs` |

> **判据永远是「旋转」**：把左下角顺时针转 90° 摆到左上角的位置，应该和左上角一模一样。
> 这个坑前后翻过四次车，每次都是想用更省事的办法凑：
>
> 1. `abs(p)` 镜像 → 镜像不是旋转，倾斜方向两两相反。
> 2. 旋转矩阵把镜像"翻回来" → 倾角统一了，但翻转过的两个角**被裁成一小截**
>    （盒子中心落在长轴负半边的假设只在 `k=+1` 时成立，`k=-1` 时整根跑到另一条对角线上）。
> 3. 屏幕恒定方向 `(1,-1)/√2` → 倾角一样了，但方向**不跟着角转**：只有左上角恰好对，
>    其余三角的刻斜插到臂上，左下角那根一半扎进竖臂（"从竖臂上探出的一小段"）。
> 4. 方向改成随角转、但取"顺着平分线指卡心"→ 四角终于一致了，可**选项选错了**：
>    要的是横跨平分线的切口，箭头版已经否掉（`tools/preview_shader.py` 里 `SPUR_STYLE="arrow"`
>    可以一键复现对比）。
>
> 现在的写法：**中心 = 角点沿两条边各内退 `斜刻离边距离`（`sign(p)` 还原四角，不用 `abs`），
> 方向 = 把"指向卡心"的平分线再转 90°**。四角 = 同一形状绕肘部转 0/90/180/270°，逐像素可比。
>
> 代价是**屏幕上四条刻的朝向各不相同** —— 不是 bug，正是"旋转一致"的必然结果。
> 验证：`python tools/preview_shader.py` 把四角都转回左上角排三排（现在 / 箭头 / 历史 bug），
> 打印倾角 / 长度 / 距角 / 与左上角的像素差。现在 `135.00° / 59.4 px / 201.9 px`，最大像素差 `0.0`
> （规范坐标系里 135° 就是屏幕上的"/"，45° 是"\"）。

### Animation · 动画

只有**一条**时间曲线：`速度` 定周期，一轮 = 一次呼吸 + 一次角标收放。内层明暗用 `cos`、
角标收放用 `0.5 - 0.5·cos`，两者**同频同相**（角标张到最大时最亮），所以看起来是同一口气在"呼"。

> **谁动、谁不动**：
>
> | 组 | 成员 | 时间 |
> |---|---|---|
> | `colOuter` | 最外那条细线 | **恒定**，完全不参与动画 |
> | `colInner` | 主金带 / 白热芯 / 内侧辉光 / 角标 / 斜刻 | 乘 `breathe` |
>
> 辉光放在 `colInner` 里是刻意的：它面积最大，是"呼吸"最容易被看见的部分。
> 早先辉光被归到 `colOuter`（恒定），结果细线在动、大片辉光不动，整块画面看起来像静止的
> —— 这就是"呼吸效果消失"的观感来源。现在只有最外那条细线定住，其余全部一起呼吸。

| 参数 | 默认 | 说明 |
|---|---|---|
| `速度` | 0.50 | **0.5 = 2 秒一轮**。1.0 是一秒，0.25 是四秒（慢悠悠） |
| `内层呼吸深度` | 0.24 | 内层明暗起伏。0 = 不呼吸；0.12 很克制（谷值 0.76），0.40 以上像"闪" |
| `角标最小缩放` | 0.74 | 收到多小。0.6 更明显，0.9 几乎看不出来 |
| `角标按下增亮` | 0.30 | 收到底时额外亮多少，制造"按下去"的感觉 |

明暗公式（`B` = 呼吸深度）：

```
breathe = (1 - B) + B·cos(2πt)      峰值 1.0（t = 0），谷值 1 - 2B（t = 0.5）
bs      = 1 - (1 - 角标最小缩放)·(0.5 - 0.5·cos(2πt))
```

> 早期版本在这上面还乘了一个 `闪烁深度`（3 倍频 + 5 倍频两个正弦），
> 那个高频抖动跟角标的节奏不一致，读起来是"两个东西各动各的"，已经删掉。


### Sizing · 尺寸

`Quad 宽` / `Quad 高` 由 `GoldenFrameUI`（UI）或 `GoldenFrameMesh`（3D）自动写入，
**不要手动改**，改了下一帧就会被覆盖。

### Depth · 深度测试

| 值 | 用在哪 |
|---|---|
| `8` Always | UGUI 的 Image（默认） |
| `4` LessEqual | 挂在 3D 网格 / Quad 上，**必须**，否则框会盖住挡在前面的棋子 |
| `2` Less | 极少用，需要严格小于时才用 |

## 三个最常做的改动

### 1. 换成红色（危险 / 血量低）

`GoldenFrame.mat` 复制一份改名 `GoldenFrame_Red.mat`，改这四个颜色：

```
外侧细线  #F76A5A
主金带    #FF3C24
白热芯    #FFD9C9   ← 别用纯白，会失去"烧红"感
角标      #FF6B4A
```

再把 `辉光强度` 稍微提到 0.65、`速度` 提到 0.8（危险状态应该更急）。

**这就是 shader 方案的全部成本：复制一个材质球，改四个色值。** 烘焙方案要为每种颜色重渲 36 帧。

### 2. 改速度

只调 `速度`：

| 想要的感觉 | 值 |
|---|---|
| 慢悠悠、高级感 | 0.25（4 秒一轮） |
| 默认呼吸 | 0.50 |
| 催促、倒计时 | 1.00 |
| 紧急警告 | 1.60 |

**这是烘焙方案根本做不到的**：那版只有 36 帧，放慢到 0.25 有效帧率只剩 4.5 fps，会明显一顿一顿。

### 3. 辉光太抢或太弱

- 太抢：`辉光强度` 降到 0.3，`衰减速度` 提到 30
- 太弱：`辉光强度` 提到 0.65，`衰减速度` 降到 14
- 卡面被橙雾糊住：`向内衰减倍数` 从 1.4 提到 2.2

## 在代码里控制

### 淡入淡出

shader 用的是预乘 over（`Blend One OneMinusSrcAlpha`），顶点色 alpha 同时乘在**光的强度**和**遮盖度**上，
所以**顶点色 alpha 就是整体强度**，直接用 UGUI 的方式就行：

```csharp
var cg = frame.GetComponent<CanvasGroup>();

// 淡入
float a = 0f;
while (a < 1f) { a += Time.unscaledDeltaTime * 4f; cg.alpha = a; yield return null; }
```

或者 `image.color = new Color(1, 1, 1, a)`，等效。**不需要动材质。**

alpha 为 0 = 光和遮盖一起归零 = 完全不发光，也不会留下暗边。

### 切配色

准备几个材质球（金 / 红 / 紫 / 绿），跑的时候换：

```csharp
image.material = rareToMaterial[rarity];
```

注意：换完要标记一下材质脏，让 `GoldenFrameUI` 重建实例：

```csharp
frame.GetComponent<GoldenFrameUI>().RefreshMaterial();
```

> 顺带一提：**不要**在运行时 `material.SetColor(...)` 去改共享材质——那会污染所有用同一个材质的框。稀有度差异用多个材质球更符合 Unity 的习惯，也和美术的工作流对得上。

### 暂停时停下

`_Time.y` 用的是 Unity 的缩放时间，所以 `Time.timeScale = 0` 时**框会自动静止**，这通常是想要的。

如果想让特效在暂停菜单里继续呼吸，就得在 C# 里传自己的时间：

```csharp
// shader 里把 _Time.y 换成 _UnscaledTime
mat.SetFloat("_UnscaledTime", Time.unscaledTime);
```

（这一版没做，需要的话我可以加一个 `_CustomTime` 参数。）

## 出问题怎么查

| 现象 | 原因 |
|---|---|
| **菜单弹"找不到 Shader"** | 先看下面的"shader 解析失败"两条 |
| Shader 解析失败（`Shader error in '': Parse error ... at line N`） | 最常见的是 **`[Header(...)]` 里写了中文**。该参数只能是不带引号的 ASCII 标识符，`[Header(GoldLines)]` 可以，`[Header(金线)]` 会让整个 shader 解析失败、`Shader.Find` 返回 null |
| 查解析错误的具体位置 | Unity 的 Console 只显示一句，完整报错在 `%LOCALAPPDATA%\Unity\Editor\Editor.log`，搜 `Shader error` |
| 整个元素**粉红色** | shader 编译失败了。打开 Console 看具体行号；如果是 URP/HDRP 项目，走错管线了 |
| 一片纯色，没有框 | `Image` 的 **Source Image 没清空**，它画的白色方块盖住了 |
| 框不跟着 UI 缩放 | 没挂 `GoldenFrameUI` 组件 |
| 框跑到别的地方 | `RectTransform` 的 pivot 不在中心，或者父节点有旋转 |
| 边缘有锯齿 | 检查 Canvas 的 `pixelPerfect` 是否开着；或者元素太小（< 100px）时线宽被压到亚像素 |
| 改了 `.mat` 没反应 | 选中对象重新点一下，或者调用 `RefreshMaterial()` |
| 框能挡住点击 | `Image` 的 `Raycast Target` 没取消 |
| 3D 里框**穿透棋子和桌子** | 材质的 `深度测试` 还在 `Always`。改成 `LessEqual`（4） |
| 3D 里框贴不住表面、边缘闪 | 和格面共面了，抬高 2 mm（`localPosition.y = 0.002`） |
| 3D 里框的线宽跟格子大小不成比例 | 没挂 `GoldenFrameMesh`，shader 拿的还是默认 `_QuadW/_QuadH` |
| **浅色 / 白色卡面上框发白、几乎看不见** | 辉光叠在金带上把绿色通道顶到 1.0 了。`实线底下压掉的辉光` 调到 0.75～1.0（见「Contrast」一节） |
| **框外面有一圈黑边 / 暗缝** | `深色描边 · 强度` 不是 0。它是为了白底硬压出来的，正常用不着，设回 0 即可 |
| 浅色卡面上框周围糊一圈橘色 | `向内衰减倍数` 太小。给到 1.4 以上 |
| **四角斜刻看着不一致** | 跑 `python tools/preview_shader.py`，看 `Preview_Corners.png`：四角都转回左上角的位置排成三排，第一排四个必须**长得一模一样**。数字看「倾角 / 长度 / 距角 / 与左上角的像素差」，现在应为 `135.00° / 59.4 px / 201.9 px / 0.0`（历史上翻过四次车，见「Brackets」一节） |
| **四条斜刻在屏幕上朝向不一样** | 正常的。判据是"左下角转 90° == 左上角"，刻是横跨每个角的平分线的，四个角的平分线朝向本就不同，所以屏幕朝向也必须不同 |
| **框外还在发光 / 有一大片橙雾** | `haloMask` 那一刀没生效。检查 `_OuterInset` / `_OuterWidth` 是不是被改到 `d > 0` 了 |
| **呼吸看不出来** | ① `内层呼吸深度` 是不是 0；② 播放头是不是停在 `t = 0`（峰）；③ `整体亮度` 太大导致整条带子全被钳到 1.0 —— 全钳住之后明暗差就没了，`整体亮度` 压到 0.9 左右再看 |
| **框外辉光没了** | 故意的。框外现在完全透明（`d > 0` 一个像素都不写），只保留框内的辉光 |
| 内层呼吸幅度太大 / 太小 | `内层呼吸深度`。0.24 = 峰值 1.0 谷值 0.52；0.12 = 谷值 0.76 |
| **Console 刷 `SendMessage cannot be called during Awake, CheckConsistency, or OnValidate (GoldenFrame_Quad: OnMeshFilterChanged)`** | 在 `OnValidate` / `OnEnable` 里给 `sharedMesh` 赋值了。修法见「三个必须知道的点 ④」：赋值只能发生在 `delayedCall` 或 `Update` 里。工程里的 `GoldenFrameMesh.cs` 已修（`OnValidate` → `ScheduleRefresh`），**Unity 侧那份如果还是旧代码，覆盖过去再 Reimport** |

## 想自己改算法

打开 `GoldenFrameUI.shader`，找到 `frag` 函数，五个片段各管一件事：

| 代码位置 | 管什么 | 改这里能干什么 |
|---|---|---|
| `RoundedBox(...)` | 卡片轮廓 | 换成别的 SDF 就是别的形状（六边形、胶囊、带凹口） |
| `Band(...)` × 3 | 三道线 | 加一行就是第四道线；改 `inset` 就是挪位置 |
| `halo` | 辉光 | 换成别的衰减曲线（比如 `1/(1+x²)`） |
| `bracket` / `spur` | 角标 / 斜刻 | 换臂的形状，比如加倒角；斜刻方向是 `(sign.y, -sign.x)/√2`（随角转、横跨平分线），把它换回 `(-sign.x, -sign.y)/√2` 就变回"箭头" |
| `colOuter` / `colInner` | 外层 / 内层分界 | 现在只有最外细线在 `colOuter`（恒定）。想让细线也呼吸，把它挪进 `colInner` |
| `breathe` / `bs` | 动画曲线 | 换缓动函数、加相位偏移 |

**改完不用重跑 Blender**，Unity 会在 1 秒内重新编译，直接看效果。这是 shader 最舒服的地方。

想先看到效果又不想动 Unity，可以跑：

```bash
python tools/preview_shader.py
```

它用 numpy 把同一套算法在 CPU 上复现一遍，输出：

| 文件 | 看什么 |
|---|---|
| `Preview_Shader_Loop.gif` | 整周期循环动图（2 秒 = `速度` 0.5 的一轮）。**判断呼吸节奏**用这个 |
| `Preview_Shader_Sheet.png` | 四个时刻的整框（看呼吸幅度） |
| `Preview_Corners.png` | 四角都**转回左上角的位置**排成三排（现在 slash / 上一版 arrow / 历史 bug），第一排四个必须长得一模一样 |
| `Preview_Shader_vs_Bake.png` | 和烘焙帧并排（只能对几何，亮度已不同步，见下） |
| `Preview_LightDark.png` | 白底 / 深底 × 加色 / 预乘 |

脚本跑完还会在终端打三张自检表：**四角旋转一致性**（倾角 / 长度 / 距角 / 与左上角的像素差，
四角必须是同一个数、最大像素差 0）、**亮度**（最外细线自身波动 `0.0000`、主带 > 0.2、框外 61 708 个像素 `add` 全 0）、
**呼吸相位**（谷值与角标最小同相）。任何一行对不上，说明公式又被改歪了。

改了 shader 的默认值要同步改脚本里的常量，否则对照图会骗人。

## 和烘焙版的数值对应

> **注意：动画已经分叉。** 烘焙帧（`../frames/`）用的还是旧曲线
> ——外层也参与明暗、内层还带 3/5 倍频闪烁、四角斜刻是**镜像**出来的（方向两两相反，
> 左下角那根还会扎进竖臂），而 shader 里已经是**旋转**（四角同一形状转 90°）。
> 几何、配色、线宽仍然一一对应，**亮度曲线和斜刻摆法不再相同**。
> 要两版重新对齐，得重跑 `build_vfx_golden_frame.py`（约 3 分钟）。

| 概念 | 烘焙脚本 | Shader |
|---|---|---|
| 主带内缩 / 线宽 | `L_MAIN_INSET` / `L_MAIN_W` | `_MainInset` / `_MainWidth` |
| 白热芯宽 | `L_CORE_W` | `_CoreWidth` |
| 角标离边 / 臂厚 / 臂长 | `BRK_OFF` / `BRK_T` / `BRK_LEN` | `_BracketOffset` / `_BracketThickness` / `_BracketLength` |
| 角标最小缩放 | `CORNER_MIN` | `_BracketMin` |
| 呼吸（内层） | `glow_mult(t)` 里的 `0.93 + 0.07·cos(2πt)` | `_Breathe` |
| 高频闪烁 | `glow_mult(t)` 里的 `sin(6πt) / sin(10πt)` | **已删除** |
| 帧数 → 速度 | `FRAMES / FPS`（36 / 18 = 2 s） | `_Speed = 0.5` |

现在 shader 里只有这一条曲线：

```
breathe = (1 - _Breathe) + _Breathe·cos(2πt)      t = _Time.y · _Speed
角标    bs = 1 - (1 - _BracketMin)·(0.5 - 0.5·cos(2πt))
```

两项都是 `cos(2πt)` 的函数，频率天然一致；周期由 `_Speed` 唯一决定，改速度两者一起变。
